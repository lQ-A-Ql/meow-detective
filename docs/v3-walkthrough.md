# V3 Investigation Walkthrough

This guide walks through a complete V3 investigation flow. It assumes the V3 evidence graph, case notebook, rule pack system, and batch processing are available. See `docs/v3-plan.md` for stage-level detail on each feature.

## 0. Prerequisites

- Forensics Workbench V3 installed
- One or more evidence sources available (disk image, file tree, or container)
- Optional: custom rule packs (`.toml` files) for domain-specific correlation

---

## 1. Open a Case and View the V3 Dashboard

1. Launch the application. From the Case Home, create a new case or open an existing one.
2. Once the case is open, navigate to the `/v3` dashboard. This replaces the V2 `/v2` governance page.
3. The V3 dashboard displays:
   - **Graph Statistics**: total node count, edge count, node-type distribution (File / Artifact / TimelineEvent / Entity / Lead / NotebookEntry), edge-type distribution (Contains / References / CorrelatesWith / Cites / Annotates / Precedes / DerivesFrom), graph density, and largest connected component size.
   - **Platform Coverage**: artifact family counts for the production platforms (Windows / Linux / Cross, where Cross means both supported platforms).
   - **Rule Pack Coverage**: loaded packs, rule counts, lead counts per pack, verification status.
   - **Batch Status**: active/completed/failed batch jobs, if any.
   - **Governance Signals**: evidence-graph integrity, platform-coverage minimums, rule-pack-required-loaded, batch-recovery-tested.

On a fresh case, the graph is empty — node and edge counts are zero. The dashboard shows "No evidence imported."

---

## 2. Import Evidence and Watch the Graph Populate

1. Go to **Import** and select an evidence source (e.g., a RAW disk image, an E01 file, or a file-tree directory).
2. Choose import options for the persisted Windows or Linux data-source platform, indexing scope, and whether to run loaded rule packs after import. Platform admission and capability filtering are backend-owned.
3. Start the import. During import the application:
   - **Catalog phase**: walks the file system tree and creates File nodes. Parent-child relationships become `Contains` edges. The File Browser becomes available incrementally.
   - **Artifact extraction phase**: runs only parsers allowed for the persisted platform (EVTX, Prefetch, LNK, Registry, etc. for Windows; Linux artifact families for Linux; browser/email capabilities shared by the supported platforms where applicable). Each extracted artifact becomes an Artifact node, with `References` edges to the source File node.
   - **Timeline population**: creates TimelineEvent nodes from file timestamps and artifact timestamps, linked via `References` edges.
   - **Entity extraction**: regex- and structure-based extraction of Person (email addresses, usernames), Device (hostname, volume serial), and Account (SID, UID) entities, linked via `DerivesFrom` edges.
   - **Correlation** (if enabled): executes loaded rule packs against the graph, producing `CorrelatesWith` edges with confidence and rule provenance.

4. While the import runs, you can already browse the file tree and view partial results. The `/v3` dashboard updates live as nodes and edges are written.

5. After import completes, return to `/v3`. You should see:
   - File nodes: count matches the cataloged file tree.
   - Artifact nodes: counts per artifact family (Prefetch, LNK, Registry, etc.).
   - TimelineEvent nodes: count matches file + artifact temporal events.
   - Entity nodes: persons, devices, and accounts extracted.
   - Lead nodes: correlation leads generated by rule packs.
   - Edge counts: Contains (file tree), References (artifact-to-file, timeline-to-file), CorrelatesWith (correlation leads), DerivesFrom (entity-to-source).

---

## 3. Browse Graph Statistics

From the `/v3` dashboard, drill into graph statistics:

1. **Node type distribution**: click on a node type (e.g., Artifact) to see counts by artifact family.
2. **Edge type distribution**: click on CorrelatesWith to see lead counts by rule pack and confidence level.
3. **Largest component**: the graph's largest connected component shows how evidence items interconnect. A large, densely connected component is expected for a heavily-used system.
4. **Provenance coverage**: what percentage of edges carry parser/rule provenance metadata. This should approach 100% for all correlation edges.

Clicking any statistic navigates to the relevant detail view (File Browser filtered by node type, Artifacts list filtered by family, or Correlation Workspace).

---

## 4. Explore the Evidence Graph

The evidence graph unifies browsing across previously separate views:

1. **File Browser**: now renders File nodes fetched via graph traversal. Clicking a file shows its neighborhood: parent/child `Contains` edges, linked Artifact nodes (`References` edges), and any `CorrelatesWith` edges to leads. The file's neighborhood is displayed inline — no need to switch tabs.

2. **Timeline**: now renders TimelineEvent nodes. Clicking an event shows its linked File/Artifact nodes, any `Precedes` edges for temporal ordering, and related Entity nodes. Filter timeline events by node type (File-derived vs. Artifact-derived).

3. **Artifacts**: now renders Artifact nodes with linked File nodes (source file) and TimelineEvent nodes. Clicking an artifact shows its provenance chain: which parser extracted it, at what time, with which parser version.

4. **Correlation Workspace**: now consumes `CorrelatesWith` edges directly from the graph. Each lead (Lead node) has edges to the source evidence nodes, carries confidence (Strong/Moderate/Weak), and provenance (rule pack + rule id). Click a lead to see its neighborhood: the source nodes that triggered the rule.

5. **Provenance chain**: click any edge to see:
   - Source rule or parser name
   - Extraction/correlation timestamp
   - Parser/rule pack version
   - Confidence or field guarantee level

---

## 5. Run Correlation and Inspect Leads

1. If correlation was not run during import, go to **Correlation Workspace** and click "Run Correlation."
2. Select which loaded rule packs to execute (default: all validated packs).
3. The correlation engine walks the graph for each rule, matching source-node types against field predicates, and creates `CorrelatesWith` edges with provenance.
4. Lead counts appear in the Correlation Workspace and on the `/v3` dashboard under "Rule Pack Coverage."
5. Click a lead to expand:
   - **Lead summary**: generated description of why the lead was created.
   - **Source nodes**: the File, Artifact, or TimelineEvent nodes that matched the rule.
   - **Edge detail**: confidence level, rule pack name + rule id, match signals (which fields matched).
   - **Neighborhood**: one-click traversal to related evidence.

6. Leads can be tagged (Confirmed, FalsePositive, NeedsReview) for status tracking. Tags appear on the lead node and are queryable.

## 6. Use the Case Notebook to Document Findings

The Case Notebook captures investigator observations with direct evidence citations.

1. Open the **Notebook Panel** (sidebar or dedicated page).
2. Click "New Entry." Choose an entry type: Observation, Hypothesis, Finding, Action Item, or Conclusion.
3. Write notes in the markdown editor. Use the toolbar or markdown syntax for formatting.
4. To cite evidence, click the **Citation Picker** button. A search dialog opens:
   - Search files by path/name.
   - Search artifacts by type and name.
   - Search timeline events by timestamp range and description.
   - Search leads by summary.
   - Search other notebook entries by title.
5. Select one or more items to cite. Each citation appears inline in the notebook entry as a clickable link (e.g., `[File: C:\Users\...\NTUSER.DAT]`, `[Artifact: Prefetch CMD.EXE-...]`).
6. Clicking a citation navigates to the cited evidence item and highlights it in its respective view.
7. Entries can be threaded: reply to an existing entry to create a child entry. Threading preserves investigation narrative.
8. Entries have a status: Draft → Reviewed → Final. Filter entries by status to track review progress.

**Example notebook entry:**

```markdown
# Finding: Suspicious executable run from Temp

Prefetch evidence shows `suspicious.exe` executed from
`C:\Users\jdoe\AppData\Local\Temp\` with high run count.

Cited evidence:
- [Prefetch: SUSPICIOUS.EXE-XXXXXX.pf]
- [File: C:\Users\jdoe\AppData\Local\Temp\suspicious.exe]

This correlates with a Registry Run key persistence entry:
- [Registry: HKLM\...\Run\SuspiciousStartup]
- [Correlation Lead: Prefetch-Temp-to-Registry-Run]

Action: escalate for malware triage.
```

## 7. Load and Verify Rule Packs

Rule packs define what correlation logic runs against the evidence graph. Packs are versioned, validated, and can be shared.

1. Go to **Settings > Rule Packs** or the **Rule Pack Manager** in the V3 dashboard.
2. The manager lists currently loaded packs with status:
   - **Valid**: parsed, schema-validated, fixture hashes match (if applicable).
   - **Valid with warnings**: minor issues (e.g., fixture hash mismatch but pack is new).
   - **Invalid**: schema violations — pack cannot be loaded.
3. Click "Load Pack" and select a `.toml` file. The pack is parsed and validated:
   - Schema check: all required fields present, types correct.
   - Reference check: all `source_family` and `target_type` values are known to the product.
   - Fixture check: if the pack declares `expected_fixtures`, hashes are verified against installed fixtures.
   - Overlap check: warns if rules overlap with existing packs.
4. After validation passes, the pack is loaded and its rules are available for execution.
5. Built-in packs ship with the product:
   - `v2-standard.toml`: reproduces all V2 hardcoded correlation rules (backward compatibility).
   - `windows-user-activity.toml`: standard Windows user activity correlation.
   - `browser-analysis.toml`: browser history and download correlation.
6. The `/v3` dashboard "Rule Pack Coverage" section shows:
   - Which rule families (e.g., Prefetch-to-File, Registry-to-Timeline, BrowserHistory-to-Download) are covered.
   - Overlap/conflict between packs.
   - Verification status: if an org-level `verification.toml` requires specific packs, the dashboard shows "3/5 required packs loaded and reviewed."

---

## 8. Org-Level Verification Configuration

For labs that require standardized checks:

1. Create a `verification.toml` file in the case directory:
   ```toml
   [verification]
   required_packs = [
       "windows-user-activity",
       "browser-analysis",
       "email-correlation"
   ]
   min_review_status = "Reviewed"
   ```

2. Place the file at `<case_root>/verification.toml`.
3. The `/v3` dashboard reads this configuration and displays verification status:
   - Green check: all required packs loaded and executed; all findings reviewed.
   - Yellow warning: some packs not loaded or findings not reviewed.
   - Red: required pack missing or validation failed.
4. The release scorecard gate `rule-pack-required-loaded` enforces this before export or case closure.

## 9. Create a Batch Plan for Large Cases

For multi-TB cases where interactive import is impractical, use the batch subsystem.

1. Go to **Batch > New Plan** to open the **Batch Plan Builder**.
2. **Step 1 — Select Data Sources**: choose one or more evidence sources (RAW, E01, file trees). For a large case this might be a multi-TB RAID image or multiple E01 segments.
3. **Step 2 — Select Phases**:
   - **Mount**: open and validate evidence sources.
   - **Catalog**: walk file system, create File nodes, compute hashes.
   - **Extract Artifacts**: run parsers (select which artifact families).
   - **Index**: build/increment the search index.
   - **Correlate**: execute loaded rule packs.
   - **Export** (optional): generate reports.
4. **Step 3 — Configure Resources**:
   - Memory ceiling (e.g., 4 GB)
   - Thread count (e.g., 4)
   - The UI shows sensible defaults based on host machine specs.
5. **Step 4 — Review**: summary of selected sources, phases, and resource limits. Click "Start Batch."
6. The batch job appears in the **Batch Monitor**:
   - Overall progress bar.
   - Phase list with individual progress bars and states (Queued → Running → Completed).
   - Elapsed time and estimated remaining.
   - Live log tail (last 20 lines).
7. While the batch runs, completed phases are available:
   - After Catalog completes, the File Browser shows the file tree.
   - After Extract Artifacts completes, the Artifacts view shows extracted items.
   - After Index completes, search is available.
8. If the application crashes or is closed:
   - On restart, the incomplete batch is detected.
   - The Batch Monitor offers **Resume**: phases resume from their last checkpoint.
   - Completed phases are not re-run.
9. From the Batch Monitor you can **Pause** (checkpoints current phase and stops), **Resume** (continues from checkpoint), or **Cancel** (stops and marks the job as cancelled).
10. After all phases complete, the batch result summary shows: files cataloged, artifacts extracted, leads found, search documents indexed, and total wall time.

---

## 10. Export the Investigation Report

1. Go to **Reports > New Report**.
2. Select export format: HTML, JSON, CSV, or Evidence Bundle.
3. Select what to include:
   - **Evidence Graph Summary**: node/edge counts, type distribution.
   - **Platform Coverage**: artifact families per platform.
   - **Correlation Leads**: all leads or filtered by tag/confidence.
   - **Case Notebook**: all Reviewed/Final entries with embedded citations.
   - **Investigation Timeline**: step history (imports, searches, correlations, annotations).
   - **Rule Pack Coverage**: loaded packs, rules executed, leads per pack.
4. Generate the report. The V3 report includes:
   - Graph-derived correlation summary.
   - Structured lead details with provenance.
   - Notebook entries with clickable citations (HTML).
   - Step replay summary (what was done, in what order).
   - Platform and parser coverage matrix.

## Quick Reference: V3 Investigation Flow

```
Create/Open Case
      │
      ▼
  /v3 Dashboard (graph stats, empty)
      │
      ▼
  Import Evidence (interactive or batch)
      │
      ├── Mount → Catalog → File nodes + Contains edges
      ├── Extract Artifacts → Artifact nodes + References edges
      ├── Build Timeline → TimelineEvent nodes
      ├── Extract Entities → Entity nodes + DerivesFrom edges
      └── Correlate → Lead nodes + CorrelatesWith edges
      │
      ▼
  /v3 Dashboard (populated graph statistics)
      │
      ├── Browse File Browser (graph-backed)
      ├── Browse Timeline (graph-backed)
      ├── Browse Artifacts (graph-backed)
      └── Correlation Workspace (graph-backed leads)
      │
      ▼
  Load Rule Packs → Verify Coverage → Run Additional Correlation
      │
      ▼
  Document in Notebook → Cite Evidence → Review Findings
      │
      ▼
  Export Report (graph summary + correlation + notebook + steps)
```
