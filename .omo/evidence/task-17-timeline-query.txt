Current behavior observed before change
- Repository queries ordered only by `ORDER BY ts DESC`, which leaves identical timestamp pagination dependent on SQLite tie behavior.
- Migration `0005_timeline_events.sql` had `idx_timeline_case_ts`, `idx_timeline_type`, and `idx_timeline_source`; it did not have indexes matching deterministic `ts DESC, id ASC` ordering.

Implementation notes
- `TimelineRepo::query` and filtered queries now use `ORDER BY ts DESC, id ASC`.
- Added repository-level case-aware filtered helper methods for query/index coverage without changing the app-service DTO/API shape.
- `row_to_timeline_event` now tolerates a nullable/malformed legacy `ts` value by loading the default timestamp, preserving read behavior for missing timestamp rows while sorting those rows last under SQLite DESC ordering.
- Added migration `0021_timeline_query_indexes.sql` with:
  - `idx_timeline_ts_id ON timeline_events(ts DESC, id ASC)`
  - `idx_timeline_case_ts_id ON timeline_events(case_id, ts DESC, id ASC)`
  - `idx_timeline_type_ts_id ON timeline_events(event_type, ts DESC, id ASC)`
  - `idx_timeline_case_type_ts_id ON timeline_events(case_id, event_type, ts DESC, id ASC)`
