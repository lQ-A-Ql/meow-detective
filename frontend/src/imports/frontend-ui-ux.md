# Frontend UI/UX Design Proposal

## 1. 目标

本文档定义本项目第一版前端 UI/UX 设计方案，用于指导后续 React/Tauri 实现。它承接 `PRD.md`、`spec.md`、`design.md` 中已定义的产品边界和页面骨架，并将这些抽象能力落成可执行的视觉、交互与信息架构规范。

本次修订后的目标非常明确：
- **提高数据密度**
- **全局导航从侧边栏改为顶部栏**
- **色调收敛为黑白灰**
- **去掉卡片化表达**
- **让界面更像分析终端，而不是产品后台**

## 2. 用户与使用语境

### 2.1 目标用户
- 安全研究员
- 独立取证分析者
- 本地事件响应中的分析人员
- 教学与实验场景中的高级用户

### 2.2 使用语境
这不是用来展示品牌风格的页面，而是会被长时间打开、频繁切换文件、搜索、时间线和工件视图的工作台。用户首先关心的是：
- 当前案件状态
- 当前数据源位置
- 当前对象属性
- 当前任务是否完成
- 当前证据与其他证据如何关联

因此本次 UI 的核心设计逻辑不是“舒展”，而是“**高密度但不乱**”。

## 3. 设计方向

## 3.1 核心风格
采用：**黑白高密度研究终端**

这不是深色炫技风，也不是现代 SaaS 风，而是一种更接近：
- 法证实验室工作台
- 文本编辑器与分析终端的混合体
- 以边界线、排版、表格、字段组织秩序的专业工具

### 关键词
- Dense
- Flat
- Monochrome
- Precise
- Forensic
- Operational

## 3.2 设计记忆点
最应让人记住的点不是装饰，而是：

> 顶部是一条持续存在的案件控制带，下面是密集、平直、带边界线的分析区域，所有页面都像同一张工作台上的不同视角。

## 3.3 视觉策略
### 不采用
- 大面积渐变
- 明显卡片阴影
- 软性拟物层叠
- 花哨色彩状态系统
- 宽松留白主导的布局

### 采用
- 黑 / 白 / 灰主导
- 细边框和分隔线建立层级
- 小字号、密表格、稳定网格
- 顶栏承担全局导航和案件上下文
- 页面间靠结构差异而不是色块差异区分

## 4. 视觉系统

## 4.1 Typography
仍然避免 Inter、Arial、Roboto 这类过于普通的产品字体。

### 推荐字体配对
- **Display / page title**：Fraunces 或 IBM Plex Serif
- **Body / UI text**：IBM Plex Sans
- **Monospace / evidence values**：IBM Plex Mono

### 使用原则
- 页面主标题和案件标题可以保留少量衬线感，提高识别度
- 绝大多数控件、表格、导航、操作区使用无衬线
- 路径、哈希、时间戳、注册表键、对象 ID 一律使用等宽字体

### 字号策略
本次修订后整体字号更紧凑：
- 24–28：主标题
- 16–18：区块标题
- 13–14：正文与表格主文本
- 11–12：次级标签、字段名、状态说明
- 10–11：辅助元信息

## 4.2 Color Tokens

### 基础色
- `--bg`: 纯黑或近黑背景
- `--bg-elevated`: 稍亮一级的深灰
- `--bg-soft`: 极轻微灰层，用于 hover 或当前选中行
- `--line`: 中灰边框
- `--line-strong`: 亮灰强边框
- `--text`: 近白正文
- `--text-dim`: 中灰弱文本
- `--text-faint`: 更弱的辅助文本

### 状态色
尽量仍以黑白灰为主，只允许非常克制的状态偏移：
- `--ok`: 偏亮灰白
- `--warn`: 偏暖灰
- `--danger`: 偏冷浅灰
- `--active`: 纯白高亮

状态不依赖彩色，只依赖：
- 反差
- 字重
- 边框
- 下划线 / 反白 / 左侧标尺

## 4.3 Spacing System
采用更紧凑的 4pt 体系：
- 4 / 8 / 12 / 16 / 20 / 24 / 32

使用原则：
- 主要操作区：8–12
- 面板内字段：6–10
- 页面区块：16–20
- 表格行高：紧凑优先

## 4.4 Radius System
尽量弱化圆角：
- 默认：0–4px
- 输入框/按钮：4px
- 大块区域：不依赖圆角建立层级

## 4.5 Elevation
本方案基本不依赖阴影。

层级主要依靠：
- 分隔线
- 反白
- 边框粗细
- 背景亮度微差

## 4.6 Motion Tokens
动效进一步收紧：
- 页面切换：120–180ms
- hover：只做背景或文字反差变化
- 抽屉：垂直滑出，短促、机械
- 不做弹性动画

## 5. 信息架构

## 5.1 全局工作台结构
修订后的全局结构为：

1. **顶部全局栏**
   - 主导航
   - 当前案件上下文
   - 搜索入口
   - 任务状态摘要
   - 导出入口

2. **页面级次栏**
   - 当前页面 filters / mode / 当前路径 / 当前对象范围

3. **主分析区**
   - 根据页面切换不同工作布局

4. **右侧详情检查器**
   - 固定保留，承载对象属性

5. **底部任务抽屉**
   - 任务、告警、trace

## 5.2 一级页面
- Case Home
- File Browser
- Search
- Timeline
- Artifacts
- Reports

## 5.3 永久可见上下文
- 当前案件标题
- 当前数据源或页面范围
- 搜索状态
- 运行任务摘要

## 6. 全局布局设计

## 6.1 顶部栏
顶部栏是整个工作台的新核心。

它不是普通网站导航，而是：
- 左：主导航
- 中：案件上下文与路径
- 右：全局搜索、任务摘要、导出与设置

### 顶栏必须实现的功能
- 页面切换
- 当前案件持续可见
- 当前搜索入口持续可见
- 当前任务数量持续可见

## 6.2 页面级次栏
每个页面在顶栏下方有一条更窄的次栏，用来表达该页面的局部控制：
- File Browser：当前卷 / 路径 / 文件类型过滤
- Search：query mode / filter scope / saved queries
- Timeline：时间范围 / 粒度 / 事件类型
- Artifacts：artifact family / source scope
- Reports：模板 / 导出范围 / 最近产物

## 6.3 主分析区
主分析区不再用卡片堆叠，而改成：
- 分栏
- 表格
- 线性区块
- 边框切割

分析区优先让位给：
- 表格
- 树
- 文本预览
- 事件列表
- 结构化详情

## 6.4 右侧详情检查器
右侧详情检查器仍然保留，但外观也去卡片化。

它更像“对象属性板”，而不是摘要卡：
- 一组字段
- 一组值
- 一组操作
- 一组关联链接

## 6.5 底部任务抽屉
底部抽屉保留，但风格也改为：
- 平直
- 强边框
- 终端式列表
- 极少装饰

## 7. 核心页面设计

## 7.1 Case Home
### 目标
不是欢迎页，而是案件运行总览。

### 结构
- 顶部案件摘要行
- 中部关键统计矩阵
- 下部最近任务 / 最近高价值对象 / 最近导出

### 风格
- 不用卡片堆叠
- 用横向分区 + 表格式摘要

## 7.2 File Browser
### 目标
成为最高密度的主工作页之一。

### 结构
- 左：目录树（页面内部，不是全局侧边栏）
- 中：文件表
- 下或中下：preview tabs
- 右：详情检查器

### 风格
- 树和表格密度高
- 用行选中和边界高亮表达当前焦点
- metadata / text / hex / preview 切换采用紧凑 tab

## 7.3 Search
### 目标
让搜索看起来像“分析命令面板 + 结果账本”。

### 结构
- 顶部 query 区
- 次级过滤区
- 中部结果表
- 下部或右侧 snippet / contextual preview
- 右侧详情检查器

### 风格
- 搜索结果不做大块卡片
- 高亮用反白或浅灰底，不用暖色强调

## 7.4 Timeline
### 目标
用最少视觉语言表达时间结构。

### 结构
- 时间范围条
- 粒度切换
- 时间聚合带
- 事件表
- 右侧事件详情

### 风格
- 图形简化为条带、刻度、点位
- 重点仍在事件列表和回链

## 7.5 Artifacts
### 目标
把 Windows 痕迹组织成一组稳定的证据表面。

### 结构
- 上方 artifact family 切换
- 中部结果表
- 右侧属性详情

### 风格
- 以表格为主
- family 切换做成紧凑水平或次栏模式，而不是左侧导航式堆叠

## 7.6 Reports
### 目标
让导出流程看起来像“结果整理”，不是视觉展示。

### 结构
- 顶部模板选择条
- 中部导出范围配置
- 下部最近导出记录表
- 右侧导出说明与状态

## 9. 状态与反馈设计

## 9.1 Loading
- 页面级 loading 不铺大面积 skeleton
- 优先使用行级、表级 loading
- 预览区用分段加载提示

## 9.2 Empty
空状态用一行说明 + 建议动作，不做插画式空态。

## 9.3 Error
错误表达优先使用：
- 行内错误
- 顶部状态条
- 底部任务抽屉告警

## 9.4 Success
成功状态同样克制：
- 状态文字
- 完成时间
- 可追溯的对象数

## 10. runtime.db 与任务系统的 UI 表达

## 10.1 runtime cache
不把 runtime cache 做成主功能，但可在：
- 预览状态
- 设置/调试页
- 底部抽屉

弱表达其存在。

## 10.2 任务系统
任务必须持续可见：
- 顶栏摘要
- 底部详细抽屉
- 页面局部状态行

## 10.3 development-reports
仍不进入终端用户主分析流。
建议只在：
- 调试模式
- 设置页
- 底部 trace 区

做弱入口。

## 11. 可访问性要求

- 纯黑白环境下仍要保证文字层级明显
- 焦点态必须强于 hover 态
- 状态差异不能只依赖灰度深浅，需结合字重/边框/位置
- 表格键盘导航要清晰

## 12. 窗口与响应策略

优先支持桌面宽屏：
- 1440px+
- 1280px 紧凑模式

收缩时优先：
- 压缩列宽
- 收起右侧检查器
- 折叠底部抽屉高度

不引入移动端布局。

## 13. 原型落地要求

更新后的 HTML+JS 原型必须满足：
- 顶部导航替代全局侧边栏
- 黑白灰主色
- 去卡片化
- 更高数据密度
- 表格、字段、分隔线主导结构
- 所有核心页面仍可切换

## 14. 后续实现建议

真实 React/Tauri 落地时，优先顺序应为：
1. 顶部工作台栏
2. 页面级次栏
3. 高密度表格系统
4. 右侧检查器
5. 底部任务抽屉
6. viewer tabs

## 15. 结论

这次修订后的前端不再追求“现代产品感”，而是明确转向：

> 黑白、高密度、顶栏主导、无卡片的分析型研究终端。

它应该让用户感觉自己面对的是一台真正用来工作的取证台，而不是一套被美化过的后台系统。
